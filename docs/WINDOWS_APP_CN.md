# ESP32 Touch Dashboard：Windows 软件手册

`ESP32TouchDashboard.exe` 是设备的 PC 数据配套程序。它在电脑上采集
CPU/GPU/RAM、本机 Codex／Claude Code 今日 Token 与人民币估算费用，并通过串口发送给设备。
`pc_monitor_host.py` 是其中的发送模块，同时会读取设备输出的日志。

## 安装与首次运行

1. 使用 Windows 电脑；当前打包参考环境为 Windows x64、Python 3.11。
   EXE 使用者不需要另装 Python，也不需要管理员权限。
2. 插入设备，确认设备管理器出现 COM 串口。测试板为 CH340，USB VID/PID
   为 `1A86:7523`。只有供电而没有数据的 USB 线无法传送监控数据。
3. 双击 `ESP32TouchDashboard.exe`，确认安装提示。
4. 程序安装到 `%LOCALAPPDATA%/ESP32TouchDashboard`，创建开始菜单快捷方式，
   启用当前用户登录自启并启动后台监控。
5. 从开始菜单打开 **ESP32 Touch Dashboard**，查看自启状态和控制按钮。

仓库提供 [EXE 下载入口](../dist/README.md)与 SHA-256 校验文件；维护者也可按
[开发流程](DEVELOPMENT.md)构建，或手动执行 Windows EXE package 工作流下载产物。
仓库中的下载包与 GitHub Releases 是不同入口，当前未创建独立 Release。
当前 EXE 没有代码签名，Windows 可能显示发布者未知。

## PC SCREEN：指定窗口与触摸操作

从 EXE 的控制窗口选择 **PC SCREEN：选择窗口与触摸控制**，再选择一个软件窗口。
设备上打开 **SYSTEM → PC SCREEN**。画面轻点为左键点击，按住滑动后松开为拖动，
底部 **UP / DN** 用于滚轮。返回其他页面即停止画面传输；在 EXE 中选择
“停止窗口共享与控制”可清除目标。原有监控、独立 CODEX / CLAUDE 用量继续使用同一个后台。

画面按比例缩到 160×88，再放大显示到 320×176。115200 串口用于低频操作，
不适合视频或高速游戏。黑边不接受点击；关闭目标窗口后必须重新选择，避免误控别的软件。
本版发送左键与滚轮消息，不含键盘、右键、双击或触摸实时逐点拖动。

程序会优先使用 `PrintWindow(PW_RENDERFULLCONTENT)`，并回退到传统窗口绘制和桌面像素采集。
选择时先保持窗口还原，收到画面后再最小化。浏览器、GPU 渲染软件或管理员窗口
可能黑屏、不更新或忽略操作；遇到这种情况先还原窗口。专用测试窗口、ChatGPT 和网易云音乐
已验证可采集；某些 Qt/OpenGL 窗口在最小化后拒绝 Windows 绘制请求，程序会显示“窗口无法采集”，
不会让设备继续显示黑屏假画面。

需要把运行日志和配置放在其他磁盘时，可设置 `ESP32_DASHBOARD_HOME`；
打包 EXE 同目录已有 `config.json` 时也会使用该目录。构建时的 `-RuntimeTemp`
可另行指定 EXE 解包目录；该路径嵌入本机包，分发其他电脑时请按目标环境重新构建。

## 自启与插入设备的关系

**用户登录 Windows 后，后台程序启动并等待设备。** 未插设备时不打开串口；
插入后检测并连接。COM 号变更可重新识别。这个机制需要首次安装并开启登录自启，
不是插入设备后让 Windows 自动安装或执行一个未安装的程序。

自启配置保存在当前用户：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
值名：ESP32TouchDashboard
命令："<安装目录>\ESP32TouchDashboard.exe" --background
```

控制窗口同时检查 Windows 的自启禁用标记。如果任务管理器禁用了此项，
可在程序中点击“启用开机自启”恢复，也可在任务管理器“启动应用”中检查。
公司电脑的登录策略可能影响此机制。换一个 Windows 用户需要重新安装。

设备匹配使用 VID/PID，并在可用时使用序列号／USB 位置，多个候选时也会参考
先前 COM 号。安装时只有一个匹配设备，程序会保存其身份；无匹配设备时仅保存
默认 VID/PID。多个同型号串口设备无法确定目标时，后台等待，不随机连接。
目前尚没有通过固件握手确认设备身份的能力。

## 控制窗口

| 项目 | 效果 |
| --- | --- |
| 开机自启：已启用／未启用 | 显示注册状态和 Windows 禁用标记；不等于已经完成重启验证 |
| 启用开机自启 | 注册登录自启，并恢复当前监控 |
| 关闭开机自启 | 取消下次登录自动启动，当前后台监控继续运行 |
| 暂停监控 | 保存暂停标记，几秒内释放串口；暂停状态跨登录保留 |
| 恢复监控 | 清除暂停标记，必要时启动后台，等待并连接设备 |
| 修改价格和汇率 | 用系统关联程序打开 `codex_prices.json`，当前是 JSON 编辑方式 |
| 查看运行日志 | 打开 `host.log`，查看连接、数据和异常信息 |
| COM 检查与设置 | 显示端口、自动识别 CH340、固定手动端口、释放监控后检查 FILE:PONG；保存后自动生效 |
| CH340 驱动检查与安装 | 查询 Windows PnP 状态，区分缺少驱动代码 28／设备异常／未接入，提供官方下载与本地安装入口 |
| 切换 AI 用量来源（备用） | 优先在设备主页点选 CODEX／CLAUDE；此入口暂停监控、向已连接设备发送一次切换指令，等待确认后恢复原暂停状态 |

关闭控制窗口后，后台继续运行。当前没有托盘图标；选择一个操作后通常会结束
当前控制对话框，需要再次从开始菜单打开才能操作其他项目。
“暂停”会保留一个等待进程；它不是完全退出程序。

## Token 与价格设置

本机存在可读取的 Codex 会话日志时自动更新，无需 API Key。
默认查找 `CODEX_HOME`，未设置时使用当前用户 `~/.codex`。
后台继承启动时的环境；环境变量修改后需重新启动后台才能生效。
新的电脑只能显示该电脑上的日志统计，不会自动带上旧电脑的用量。

“修改价格和汇率”打开：

```text
%LOCALAPPDATA%/ESP32TouchDashboard/codex_prices.json
```

若 Windows 没有 JSON 文件关联，可用记事本手动打开。保存为有效 JSON／UTF-8，
约下一次 5 秒统计刷新后生效。JSON 不支持注释和尾随逗号。
价格文件修改会重新估算当天数据，当前没有按价格生效日期分段计价。
默认模型、长短上下文单价和公式见 [Codex 统计与价格](CODEX_USAGE_CN.md)。

AI 每日目标及限额已删除，升级安装会移除旧 `daily_goal` 配置。
`ai_source` 可为 `codex`／`claude`，记录电脑端上次选择；旧 `all` 设置迁移为 `codex`。
设备当前来源保存在设备 NVS 中，电脑后台启动、数据刷新及重连不会覆盖它。
`codex_refresh` 为刷新秒数，默认 5。
后台约每两秒重新读取配置，设备配置变化时先停止旧采集线程再连接。
根目录 `start_dashboard.ps1` 只恢复监控；显式 `-AiSource claude` 才选择已连接设备的来源。

Claude Code 默认扫描 `CLAUDE_CONFIG_DIR` 或 `~/.claude/projects`。
模型名称按日志精确匹配单价，未知模型不会套用其他模型价格。

## COM 与 CH340

COM 设置的手动模式固定所选端口，端口消失时等待，不自动切换其他设备。
自动模式按 CH340 VID/PID 和已有身份匹配。连接检查暂时暂停监控，等待串口释放，
发送 `FILE:PING` 并检查 `FILE:PONG`，随后恢复原暂停状态。此响应只证明协议可用，
不构成独有设备身份握手；打开串口也可能受桥接器驱动影响引起设备复位。

驱动检查可发现没有 COM 号的缺驱动 USB 设备；未接入设备时不推断驱动缺失。
“自动下载并安装”使用 WCH 官方接口，检查 EXE 文件及有效 WCH/QinHeng 签名后，
通过 Windows UAC 请求安装权限。WCH 页面校验或网络可能阻止自动下载，
此时选择“打开 WCH 官方下载页面”，下载 `CH341SER.EXE` 后使用本地安装入口。
程序本身按用户安装无需管理员权限，驱动安装需要；安装结果需刷新 PnP 状态确认。

## 本机文件与资源

| 文件 | 用途 |
| --- | --- |
| `ESP32TouchDashboard.exe` | 已安装程序 |
| `config.json` | USB 身份、自动／手动 COM、刷新间隔、AI 来源 |
| `connection.json` | 后台暂停／采集状态，供连接检查协调串口释放 |
| `codex_prices.json` | 模型单价与汇率 |
| `host.log`、`host.log.1`～`.3` | 轮换日志，每个上限约 2 MB，总计约 8 MB |
| `agent.pid`、`agent.lock` | 后台进程信息、单实例锁 |
| `paused` | 存在即保持暂停 |
| `dialog.manifest` | 原生 Windows 对话框支持文件 |
| `error.log` | 异常时写入的错误信息 |

已验证单文件 EXE 大小约 7.4 MiB；该机后台相关进程合计工作集曾观察到约 55 MiB，
仅是一个环境下的快照，不是性能上限。PyInstaller 单文件版会解压运行时到临时目录，
启动时通常有引导和工作两个进程；实际磁盘占用还包括解压内容和日志。
不带 Qt／Electron／WebView；后续资源优化建议见 [路线图](ROADMAP_CN.md)。

本机配置、日志、进程文件、Flash 备份以及 Codex 原始日志都不应上传到 GitHub。

## 换电脑、升级与移除

### 换电脑

安装一次 EXE，接上设备并确认串口驱动；需要时复制自己的价格配置。
不要直接照搬旧 `config.json` 的 USB 位置／COM 号，安装程序可在新电脑识别设备。
新电脑上的 Codex 尚无可读使用记录时，NO DATA 是预期表现。

### 更新 EXE

当前没有自动更新器，也没有“退出后台”按钮。安装程序会拒绝覆盖仍在运行的旧 EXE。

1. 备份安装目录的 `config.json` 与 `codex_prices.json`。
2. 暂停监控，让串口释放。
3. 在任务管理器结束安装目录对应的 ESP32TouchDashboard 引导／工作进程。
   确认旧后台已结束。
4. 运行新版 EXE，或在终端调用新版 `ESP32TouchDashboard.exe --install`。
   保留设备设置、自定义价格和汇率，移除旧每日目标，迁移旧内置价格并备份；安装流程启用自启并恢复监控。
5. 检查控制窗口自启状态和设备数据显示。

已安装过程序时，直接双击下载的新 EXE可能只打开控制窗口；显式 `--install`
才会执行覆盖安装。若仍提示旧程序运行，继续检查任务管理器，不要强行覆盖文件。

### 手动移除

1. 在控制窗口关闭开机自启，再暂停监控。
2. 在任务管理器结束安装目录对应的后台进程。
3. 若要保留设置，先备份配置。然后删除
   `%LOCALAPPDATA%/ESP32TouchDashboard`。
4. 删除开始菜单快捷方式：
   `%APPDATA%/Microsoft/Windows/Start Menu/Programs/ESP32 Touch Dashboard.lnk`。

当前没有“应用和功能”卸载入口或独立卸载向导；改进计划见路线图。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 重启后不显示电脑数据 | 登录后打开控制窗口，确认自启已启用、未暂停；检查任务管理器启动应用和 `host.log`。当前验证记录未包含真实重启测试。 |
| COM 号存在但连不上 | 检查其他串口监视器、烧录工具或库存工具是否占用；关闭它们再恢复监控。 |
| 多个 CH340 同时接入 | 在 COM 设置中手动选择目标设备并检查响应。 |
| 换 USB 插口后等不到目标 | 在 COM 设置中刷新，重新选择端口或切回自动模式。 |
| CPU 温度 `--` | WMI 温度提供者通常无法提供实际 CPU 核心温度；当前电脑即可能读不到，这是传感器限制。 |
| GPU 数据 `--` | 当前主要支持 NVIDIA NVML，检查驱动；AMD／Intel 没有同等已实现路径。 |
| Tokens NO DATA | 确认该用户的 Codex 日志目录、本地今日记录、后台与设备日期；阅读日志中的 CODEX 信息。 |
| 有 Tokens、金额 `~¥--` | 检查 JSON、模型名称匹配、单价、汇率和细分 Token；不完整时不显示部分总价。 |
| 日志有 CODEX，但屏幕仍 NO DATA | 检查设备是否使用包含 UART 多行修复的新固件；旧版本会丢弃一批串口数据的后续行。 |
| 烧录失败／端口被占用 | 先暂停并等待释放，再运行烧录。固件监视器也会占用串口，结束后才恢复后台。 |

## 命令行维护入口

对**已安装的程序**可使用以下参数。默认运行打开控制窗口。

| 参数 | 功能 |
| --- | --- |
| `--install [--quiet]` | 执行安装，安静模式不弹成功提示 |
| `--background` | 登录自启使用的后台入口 |
| `--enable-autostart`／`--disable-autostart` | 切换自启；命令行 enable 本身不恢复监控，与按钮操作不同 |
| `--pause`／`--resume` | 暂停／恢复 |
| `--status <报告路径>` | 写出自启／暂停状态 JSON |
| `--self-test <报告路径>` | 写出本机用量与端口诊断；使用 EXE 内置价格模板，不验证已安装价格文件或设备收包 |

状态／自测报告包含本机路径和用量，分享前先检查内容，不提交到源码仓库。
